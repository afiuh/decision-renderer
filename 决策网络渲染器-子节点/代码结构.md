# 代码结构

**父级**：[决策网络渲染器](../决策网络渲染器.md)

## 约束

```
decision-renderer/
├── 决策网络渲染器.md          ← 决策网络本身（真源）
├── 决策网络渲染器-子节点/
└── packages/
    ├── shared/                ← 前后端共用类型
    ├── server/                ← 解析 / 监听 / 写回 / HTTP / MCP
    └── client/                ← 画布 / 布局 / 交互 / 渲染 / 编辑
```

| 原则 | 做法 |
|---|---|
| 核心无框架 | `parse` / `layout` / `write` 是纯函数，不 import React/Fastify |
| 前后端只靠协议 | server 不 import client，client 不 import server；共用类型放 `shared` |
| 布局与渲染分离 | 布局输出坐标，渲染消费坐标；渲染层不知道圆和角度 |
| 交互与几何分离 | 拖动只改角度/位移，几何重算由布局负责 |
| 一份真源 | 树只有一份（解析结果），画布状态是它的投影 |

## 边界

- **不按页面/路由组织代码**。按功能分目录（canvas / layout / drag / content / workspace）。
- **不做 monorepo 工具链**。npm workspaces 够用，不上 turbo/nx。
- **不为插件化提前抽象**。以后嵌进 dshiunx 时加一层适配即可，现在不写 plugin 接口。

## 验证

- 删掉 `client/`，`server/` 仍能独立跑起来并通过 HTTP 测试。
- 删掉 `server/`，`layout/` 的纯函数测试仍能跑。
- 任意一个功能目录（layout / drag / content）能单独读懂，不需要先读别的。
