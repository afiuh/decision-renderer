# 代码结构

**父级**：[实现模块](../实现模块.md)

## 这个模块负责什么

代码怎么组织：双包（client/server 分开）、模块划分、解耦原则、插件化路径。

## 双包结构

```
decision-renderer/
├── 决策网络渲染器.md
├── 决策网络渲染器-子节点/
├── package.json              ← workspace 根
└── packages/
    ├── server/               ← Node 服务（Fastify + ws）
    │   ├── src/
    │   │   ├── index.ts      ← 入口（HTTP + WebSocket）
    │   │   ├── parse.ts      ← 解析：目录 → 节点树 + 边
    │   │   ├── watch.ts      ← chokidar + git diff（增量）
    │   │   ├── write.ts      ← 写回（remark）
    │   │   └── api.ts        ← 路由
    │   └── package.json
    │
    └── client/               ← 前端（Vite + React）
        ├── src/
        │   ├── main.tsx
        │   ├── canvas/       ← 画布（React Flow + 碰撞 + 连线）
        │   ├── window/       ← 内容窗口（react-rnd + Markdown）
        │   ├── layout/       ← dagre 自动布局
        │   └── web-kit/      ← 复制的 web-kit（按需）
        └── package.json
```

## 解耦原则

| 原则 | 做法 |
|---|---|
| 前后端分离 | `server/` 只依赖 `fs` + `git`；`client/` 只依赖 HTTP/WebSocket |
| 核心无框架 | `parse.ts` / `watch.ts` 是纯函数 + fs，不依赖 React/Fastify |
| 共享类型 | `packages/shared/types.ts`（前后端同一份） |
| UI 可复用 | `canvas/` 是独立组件（不依赖页面） |
| web-kit 按需复制 | 只复制需要的（`workbench/` + `styles/`），不整包复制 |

## 通信

**WebSocket（双向）**：
- 服务端 → 客户端：树变化 / 节点更新（增量）
- 客户端 → 服务端：写节点 / 新建节点 / 请求树

## 插件化路径（以后集成到 dshiunx）

```
现在（独立）                    以后（插件）
packages/server/src/*  →   包装成 Cordis 插件（ctx.decisionRenderer）
packages/client/src/canvas/* → 作为 React 组件导出（嵌入 web-kit 的 A 区）
```

**关键**：核心逻辑（parse/watch/write）不依赖 dshiunx——以后加一个 `plugin.ts` 适配层就行。
