# 同步

**父级**：[信息渲染](../信息渲染.md)

## 这个模块负责什么

文件树 ↔ 画布的双向同步，增量更新。

## 两层分工

```
实时层（chokidar）：文件保存 → 触发同步
结构层（git diff）：拿到变化文件列表 → 只重解析这些
状态层（git status）：未提交修改标记
历史层（git log/show）：节点时间线 / 回滚
```

| 层 | 工具 | 作用 |
|---|---|---|
| 实时 | chokidar | 文件变化触发 |
| 增量 | `git diff --name-only` | 只解析变化的文件 |
| 状态 | `git status` | 画布上标"未提交" |
| 历史 | `git log` / `git show` | 时间线 / 回滚 |

## 流程

```
文件保存
  → chokidar 触发
  → git diff --name-only（增量列表）
  → 只解析变化的文件
  → 画布更新（只更新变化的节点/边）

画布操作（新建/删除/移动）
  → 写文件
  → chokidar 触发（忽略自己写的）
  → 增量解析 → 画布更新
```

## 关键点

| 点 | 方案 |
|---|---|
| 防循环 | 写文件时标记来源，监听忽略自己触发的 |
| 去抖 | 200ms 合并 |
| 全量兜底 | 首次加载 / git 操作后全量重解析 |
| git 盲区 | git 看不到"编辑器未保存"——chokidar 负责实时，git 负责结构/历史 |

## 为什么用 git

- **增量**：`git diff --name-only` 天然给出"哪些文件变了"
- **状态**：`git status` 区分"已提交/未提交"
- **历史**：`git log` 就是节点的时间线
- **回滚**：`git show` 拿到任意版本
