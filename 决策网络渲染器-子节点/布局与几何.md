# 布局与几何

**父级**：[决策网络渲染器](../决策网络渲染器.md)

## 为什么是圆形扩散

树形布局（dagre/elk）在深度大时会退化成一条长带：每层往一个方向排，展开三层就要横向滚很久，人看不到全貌。

圆形扩散把每个节点的子节点绕它排一整圈。展开只增加局部半径，整体始终是一团可缩放的形状。

## 约束

- **根在中心**。多个根时绕中心均分。
- **每个展开节点，子节点绕它全圆（360°）分布**。
- **角度按子树占位分配**：占位 = 该子树展开后可见的节点数（折叠的子树算 1）。占位大的子树分到更大的扇区。
- **半径按子节点自己的占地算**，不是按层算。见[半径延长](./布局与几何-子节点/半径延长.md)。
- **布局是纯函数**：输入（树、展开集、用户拖过的位置），输出（中心坐标、父子关系、连线长度、子孙列表）。不碰 DOM、不碰 React、不读文件。
- **用户拖过的位置优先**。重算布局时，拖过的节点保持用户给的角度，没拖过的按算法排。

## 边界

- 布局**不写回真源**。`.layout.json` 是运行时数据，可删；删了重新算。
- 布局**不负责推挤**。圆形布局本身不重叠，推挤会和"保持半径"冲突。
- 布局**不决定卡片尺寸**。尺寸由渲染层提供，布局只消费。

## 验证

- 任意展开组合、任意深度：节点卡片互不重叠，子节点的圆不覆盖祖先卡片。
- 同一输入（树 + 展开集 + 拖动记录）跑两次，坐标完全一致。
- 折叠一个子树，其余节点的相对角度**顺序**不变。
