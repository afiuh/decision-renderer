# 界面设计

**父级**：[决策网络渲染器](../决策网络渲染器.md)

## 为什么

工具现在只认一个工作区：换一个决策网络就要改配置、重启。实际有好几棵（dshiunx、decision-renderer、以后更多），人要一个个找，AI 也要一个个读。

界面要做的只有一件事：**把多个决策网络当成"项目"集中摆出来，点开就进对应工作区，像系统桌面一样切换。** 树的渲染、编辑、AI 接口都不变，变的是"怎么在多个项目之间走"。

## 布局

只用 web-kit 的三个区，不用的区不渲染，不凑数：

| 区 | 内容 |
|---|---|
| **D 上栏** | 左：工作区条（编号 1 2 3…，当前高亮）；右：新建子节点、搜索 |
| **C 侧栏** | 第一组「项目与导入」：已导入项目列表 + 新建项目 + 导入 |
| **A 主区** | 当前工作区的画布（React Flow） |

**参考**：web-kit 的契约——区域是边界，内容是渲染函数。框架不认识"项目/决策网络"。

## 约束

### 项目

- **一个项目 = 一个决策网络根目录**（含 `X.md` + `X-子节点/`）。
- 项目有 id（目录路径）和显示名（根节点标题，取不到时用目录名）。
- **项目列表来自"已导入记录"**，持久化在后端（不是每次扫描、也不是前端硬编码）。
- **导入** = 点"导入" → 弹出目录选择窗口 → 选一个已有目录 → 校验是决策网络 → 加入列表。已导入的不重复。
- **新建项目** = 点"新建" → 弹出窗口填名称 + **选保存位置**（目录选择器）→ 在选中的位置建目录 + 根节点骨架 → 加入列表并自动打开为工作区。
- 目录选择窗口要能：逐级进入、返回上级、显示当前路径、新建文件夹。
- 项目列表标出"已打开"状态，和"当前工作区"是两件事。

### 工作区

- **一个工作区 = 一个打开的项目 + 一块画布**。
- 编号从 1 开始，按打开顺序排；关闭一个后**重新编号，不留空号**。
- 上栏左侧显示编号；当前工作区高亮；点击切换。
- **同一个项目只占一个工作区**：再点列表里的它 = 切过去，不重复开。
- 工作区数量不设上限；多了横向滚动。
- **切换工作区不销毁画布状态**：展开集、拖动角度、内容节点、视口都保留，切回来和切走前一模一样。
- 关闭工作区：工作区条上的 ×（或中键）；关闭不删项目，项目仍在侧栏列表里。

### 侧边栏

- 「项目与导入」是第一组，默认展开。
- 项目列表：点一下 = 打开/切到它的工作区。
- 新建项目：弹窗（名称 + 保存位置）→ 建目录 + 骨架 → 自动打开。
- 导入：弹目录选择窗口 → 选已有目录 → 加入列表。
- 列表顺序：最近打开的在前（同一次会话内）。

### 上栏

- **左**：工作区条（编号 + 当前高亮 + 关闭）。
- **右**：新建子节点（作用于当前工作区选中的节点）、搜索框。
- 工作区条在左侧，和侧栏的分组不是一回事：侧栏是"有哪些项目"，上栏是"打开了哪些"。

## 边界

- **只渲染用到的区**（C/D/A），不为了"五区完整"塞空区。
- **不做并排多画布**。多项目靠工作区切换（参考 Hyprland workspace）。
- **不做项目内多标签页**。一个项目一个画布。
- **不做工作区拖拽排序**。先按打开顺序。
- **删除项目 = 从列表移除记录**，不删磁盘文件；重命名不做（在文件系统里改）。
- **关闭项目 = 关闭它的工作区**，项目仍留在列表里。
- **不做权限/多人/审批**。
- **不改树的渲染和编辑**。工作区只换"哪棵树"，不换"树怎么画"。

## 验证

- 点"导入" → 目录窗口能逐级浏览 → 选一个决策网络目录 → 侧栏出现该项目。
- 点"新建" → 弹窗能填名称、选保存位置 → 磁盘对应位置出现目录和根节点文件，工作区自动打开。
- 侧栏点一个项目 → 上栏出现工作区 1，画布显示它。
- 点第二个项目 → 工作区 2 出现并切过去；切回 1，展开集/拖动角度/内容节点/视口都还在。
- 关闭工作区 2 → 编号重排，只剩 1；项目仍在侧栏。
- 再点侧栏里已在工作区 1 的项目 → 切过去，不新增工作区 2。
- 上栏右侧"新建子节点"作用于当前工作区选中的节点，不影响其他工作区。
