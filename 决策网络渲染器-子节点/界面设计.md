# 界面设计

**父级**：[决策网络渲染器](../决策网络渲染器.md)

## 要做什么

把多个决策网络当成「项目」集中管理：侧栏列出项目，点开就进对应工作区，多个项目用工作区切换。

> 用户（2026-11-07，界面设计）：
> "决策网络是文件不同的决策网络需要集中按照文件项目的方式管理，
> 增加侧边栏，里面放上第一个功能组，项目和导入"

## 为什么要做

工具原来只认一个工作区，换一棵树要改配置、重启。实际有好几棵（dshiunx、decision-renderer、以后更多），人要一个个找，AI 也要一个个读。

> 用户（2026-11-07）：
> "打开里面是已经导入的项目和一个新建项目，然后打开项目就是在画布区里呈现"

## 怎么做

### 布局：只用三个区

| 区 | 内容 |
|---|---|
| **D 上栏** | 左：工作区条（编号 1 2 3…，当前高亮）；右：新建子节点、搜索 |
| **C 侧栏** | 第一组「项目与导入」：已导入项目列表 + 新建项目 + 导入 |
| **A 主区** | 当前工作区的画布 |

> 用户（2026-11-07）：
> "上栏左侧就是换成放工作区新建子节点的按钮移动到上栏的右侧"

不用的区不渲染，不为了"五区完整"塞空区。

> 用户（2026-11-07）：
> "不用的就不要，不需要强行凑"

### 项目

- **一个项目 = 一个决策网络根目录**（含 `X.md` + `X-子节点/`）。
- 项目列表持久化在后端 `~/.config/decision-renderer/projects.json`，不是每次扫描。
- **导入**：弹目录选择窗口 → 逐级浏览 → 选一个已有目录 → 校验目录里至少有一个 `.md` → 加入列表。
- **新建**：弹窗填名称 + 选保存位置 → 在选中位置建目录 + 根节点骨架（`# 名称`）→ 加入列表并自动打开。

> 用户（2026-11-07）：
> "就像给AI指定工作区一个操作，新建项目的话点了之后弹出窗口要选保存位置"

- **关闭项目** = 关闭它的工作区，项目仍留在列表里。
- **删除项目** = 从列表移除记录，**不删磁盘文件**（确认框写明这一点）。

> 用户（2026-11-07）：
> "关闭项目和删除项目没做吗"

### 工作区

- **一个工作区 = 一个打开的项目 + 一块画布**。
- 编号从 1 开始，按打开顺序排；关闭一个后重新编号，不留空号。
- 上栏左侧显示编号，当前高亮，点击切换；工作区条 hover 出现 ×。
- **同一个项目只占一个工作区**：再点列表里的它 = 切过去，不重复开。
- **切换工作区不销毁画布状态**：展开集、拖动角度、内容节点、视口都保留，切回来和切走前一模一样。
- 每个工作区一个 Canvas 实例，切换时 `display` 隐藏、不卸载。

> 提炼自用户（2026-11-07）：
> "打开多个项目就是在有多个画布区参考我系统桌面的工作区机制"
> —— 系统桌面切工作区不会重置窗口状态

### 侧栏

- 可拖宽（140–480px），可收起（26px 圆钮），箭头方向随展开/收起变化。

> 用户（2026-11-07）：
> "边栏是可拉伸可折叠的"

- 项目行 hover 显示「关」「删」两个按钮。

## 如何验证自己做对了

- 点「导入」→ 目录窗口能逐级浏览 → 选一个决策网络目录 → 侧栏出现该项目。
- 点「新建」→ 弹窗能填名称、选保存位置 → 磁盘对应位置出现目录和根节点文件，工作区自动打开。
- 点侧栏一个项目 → 上栏出现工作区 1，画布显示它。
- 点第二个项目 → 工作区 2 出现并切过去；切回 1，展开集/拖动角度/内容节点/视口都还在。
- 关闭工作区 2 → 编号重排，只剩 1；项目仍在侧栏。
- 再点侧栏里已在工作区 1 的项目 → 切过去，不新增工作区 2。
- 关闭项目 → 工作区消失，项目仍在列表；删除项目 → 列表消失，磁盘目录还在。
- 侧栏拖边界能改宽，圆钮能收起/展开。
- 人看：整体像不像系统桌面的工作区切换。
