# 决策网络 · 理论文档

## 核心

[决策网络-通用决策拓扑框架](./决策网络-通用决策拓扑框架.md) 是**本体**，其他文档都是它向不同领域的展开。

> 给定任何问题，以问题为根，向下生成决策网络：节点是功能节点——父功能定义实现空间（目标/边界/验证），子功能在约束下探索实现并反馈；同一节点可同时承担父功能和子功能；根只承担父功能，叶只承担子功能；拆到叶子可落地、可验证为止。

**决策网络的结构，就是做任何事的标准决策结构。任何事都是这样的：**

```
目标（为什么做）
  → 分解（必须做什么，子目标依赖父目标）
    → 边界（不做什么、限制）
      → 验证（什么算完成）
        → 执行
          → 反馈（偏差回改上一层）
```

从"今天吃什么"到"航母建造"，结构是同一个：

| | 今天吃什么 | 航母建造 | 写一篇文章 | 做一个插件 |
|---|---|---|---|---|
| 目标 | 吃饱/健康/省钱 | 作战能力 | 让读者理解一个判断 | 解决一类任务 |
| 分解 | 主食/菜/饮料 | 船体/动力/电子/舰载机 | 论点/论据/结构 | 解析/布局/渲染/接口 |
| 边界 | 预算/时间/忌口 | 预算/工期/法规 | 篇幅/读者/立场 | 不做什么、依赖什么 |
| 验证 | 好吃/饱 | 海试/演习 | 读者能复述推演 | 行为级测试 |
| 反馈 | 不好吃 → 调整 | 问题 → 返工 | 读不懂 → 改结构 | 测试失败 → 定位节点 |

## 一句话

> 决策网络不是"让 AI 更聪明"，是"把做任何事的标准结构显式化，让 AI 必须按结构走"：
> 判断者在高层拍板方向，AI 在低层执行，决策文件是锚点，git 保证可追溯，验证标准保证不偷懒。

## 和渲染器的关系

决策网络是**结构**（文件夹 + Markdown + git），渲染器是**看和改这个结构的入口**：

- 人：点节点就能看、能改，不用翻目录
- AI：调 HTTP / MCP 拿结构化树，不用读十几个文件

没有渲染器，AI 每次都要重新读文件、靠上下文记忆——**这正是"理解需要讲好几轮"的来源**。

## 核心概念（速查）

- **功能节点**：父功能定义实现空间（为什么/边界/什么算完成），子功能在约束下实现并反馈
- **展开判据**：每层只问"要实现当前节点，必须做什么"；去掉一个子节点，上层实现不成立 → 是依赖；仍成立 → 是分类
- **叶子判据**：能直接执行、能直接验证、不需要再拆
- **动态循环**：决策 ↔ 实践，偏差回改实现空间
- **使用形态**：脑内（根=叶，零成本）/ 轻量 / 完整（git + 行为级验证），按需外化
