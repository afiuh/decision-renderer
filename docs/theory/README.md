# 决策网络 · 理论文档

这组文档回答一个问题：**为什么需要决策网络渲染器？**

不是"因为 Markdown 不好看"，而是因为 AI 在复杂任务里有四个真实毛病，而决策网络是约束这些毛病的结构。

## 一句话

> 决策网络不是"让 AI 更聪明"，是"把解决问题的通用流程显式化，让 AI 必须按流程走"：
> 判断者在高层拍板方向，AI 在低层执行，决策文件是锚点，git 保证可追溯，验证标准保证不偷懒。

## 和渲染器的关系

决策网络是**结构**（文件夹 + Markdown + git），渲染器是**看和改这个结构的入口**：

- 人：点节点就能看、能改，不用翻目录
- AI：调 HTTP / MCP 拿结构化树，不用读十几个文件

没有渲染器，AI 每次都要重新读文件、靠上下文记忆——**这正是"理解需要讲好几轮"的来源**。

## 核心概念（速查）

- **功能节点**：父功能定义实现空间（为什么/边界/什么算完成），子功能在约束下实现并反馈
- **展开判据**：每层只问"要实现当前节点，必须做什么"；去掉一个子节点，上层实现不成立 → 是依赖；仍成立 → 是分类
- **叶子判据**：能直接执行、能直接验证、不需要再拆
- **动态循环**：决策 ↔ 实践，偏差回改实现空间
- **使用形态**：脑内（根=叶，零成本）/ 轻量 / 完整（git + 行为级验证），按需外化
