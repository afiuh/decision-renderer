## 一、一句话

> **给定一个问题，以问题为根，向下生成决策网络：节点是功能节点——父功能定义实现空间（目标/边界/验证），子功能在约束下探索实现并反馈；同一节点可以同时承担父功能和子功能；根只承担父功能，叶只承担子功能；约束是探索实现方案的手段，不是目的；拆到叶子可落地、可验证为止。父功能和子功能是相对的，具体内容没有定式，要放到具体决策网络里分析。**

---

## 二、核心结构：功能节点

决策网络的节点不是独立实体，是**功能节点**。父功能/子功能是相对关系，不是固定内容；下表只是功能位置，不代表固定字段。

| 功能 | 做什么 |
|---|---|
| **父功能** | 定义实现空间、给下层约束；具体给什么，由具体决策网络决定 |
| **子功能** | 在约束下探索实现并向上反馈；具体怎么做，由具体决策网络决定 |

同一个节点可以同时承担父功能和子功能：

| 节点位置 | 承担的功能 |
|---|---|
| **根** | 只承担父功能（没有上层约束） |
| **中间** | 同时承担子功能（承接上层约束）和父功能（给下层约束） |
| **叶** | 只承担子功能（落地，不再给下层） |

**父/子是功能，不是身份。** 一个节点对上层是子功能，对下层是父功能；不是“一个父节点生一个子节点”。

## 三、父功能与子功能的接口

父功能和子功能之间不是“任务下发”，是**实现空间的约束与实现**。父功能给什么、子功能反馈什么，没有定式；由具体决策网络的具体情境分析：

| 方向 | 父给子 | 子给父 |
|---|---|---|
| 决策内容 | 实现空间：为什么做、边界在哪、目标是什么、什么算完成 | 实现方案：怎么拆、怎么执行、实际反馈、哪里不可行 |
| 责任 | 方向/取舍/验证标准 | 拆解/执行/反馈 |
| 禁止 | 替子做实现决策 | 替父做方向决策 |

**父功能与子功能的接口必须成立**：

- 父功能不能只给“任务”，不给实现空间（边界/验证）；
- 子功能不能只给“执行”，不反馈实际约束和偏差；
- 越级 = 父功能替子功能做实现，或子功能替父功能定方向；
- 缺层 = 实现空间悬空。

## 四、节点如何展开：按“实现需要做什么”，不按问题分类

### 4.1 展开的提问

从根开始，每层只问一句：

> **要实现当前节点，必须做什么？**

不是问：

> 这件事有哪些相关问题/方面？

### 4.2 展开的判据

- 子节点是“上层实现必须依赖的环节”；
- 去掉一个子节点，上层实现不成立 → 是实现依赖；
- 去掉一个子节点，上层实现仍成立 → 是问题分类/可选，不是展开节点；
- 每层只展开当前层，不预告更下层；
- 展开到“再问就必须进入执行细节”为止（叶子）。

### 4.3 展开的方向

- **父功能 → 子功能**：父功能问“要实现我，必须做什么”，得到子功能；
- **子功能 → 父功能**：子功能实现中发现“上层实现空间不对/不可行”，反馈修正父功能；
- **同一节点同时承担两种功能**：对上是子功能，对下是父功能。

### 4.4 例子（只是例子，不是固定层数）

根：让 AI 在任务前走框架。

要实现它，必须：

1. 让 AI 停下来（否则不会想整体）；
2. 停下来后能生成整体（否则停了没用）；
3. 整体里能区分哪些不能 AI 自己定（否则越权）；
4. 能落地执行（否则整体悬空）；
5. 能根据实践修正（否则僵化）。

这不是“问题分类”，是“实现链”：1 不成立，2 不发生；2 不成立，3 没有对象；3 不成立，4 会越权；4 不成立，5 没有反馈。

具体层数、每层内容，由具体决策网络决定；上面只是这次的一个例子。

### 4.5 与问题分类的区别

| | 问题分类 | 实现展开 |
|---|---|---|
| 提问 | 有哪些相关问题 | 要实现它，必须做什么 |
| 子节点 | 并列主题 | 实现依赖 |
| 去掉一个 | 其他还能成立 | 上层实现不成立 |
| 顺序 | 可任意 | 有依赖 |
| 结果 | 清单 | 实现路径 |

## 五、决策与实践的动态循环

决策不是一次写完的，是和实践循环互优化的：

```
决策 → 实践（执行/验证）→ 发现偏差 → 修正决策 → 再实践
```

### 4.1 循环的位置

- 每个节点都可以进入循环：根、中间、叶；
- 父功能给子功能定义实现空间 → 子功能实践 → 反馈偏差 → 父功能修正实现空间；
- 中间节点同时承担两种功能：向上反馈实践偏差，向下修正子功能的实现空间。

### 4.2 决策写“为什么”，不写“死结论”

- 决策写“为什么这样做/边界在哪/什么算完成”，才能被实践检验；
- 实践发现问题 → 改决策，不是改执行再补文档；
- 决策改动 → 执行跟着改；执行改动 → 决策同步。

### 4.3 循环与拓扑的关系

- 拓扑提供结构（根—中间—叶、父子边）；
- 循环提供修正（决策↔实践）；
- 两者正交：没有拓扑，循环没有落点；没有循环，拓扑会僵化。

### 4.4 记录

- git/记录每次循环：决策、实践、偏差、修正；
- 可追溯、可回滚、可复盘；
- 循环不是“反复重写”，是“每次基于上一版修正”。

## 六、生成规则：从问题到可落地

1. **以问题为根**：写清问题、目标、边界、总体验证标准；
2. **每层只拆自己**：当前节点只决定“下一层怎么分”，不预告更下层；
3. **父功能给子功能定义实现空间**：目标/边界/什么算完成；
4. **子给父反馈**：拆解/执行/实际偏差；
5. **拆到叶子为止**：叶子必须可执行、可验证，不再拆；
6. **网络闭合**：根有方向，叶有落点，中间不悬空。

### 叶子判据（可落地）

- 能直接执行：谁做、做什么、什么时候做；
- 能直接验证：什么算完成、行为级标准；
- 不需要再拆：再拆就是执行细节，不是决策。

---

## 七、拓扑形态：开放，但不失锚点

- **深度开放**：根→中间→叶，层数不设限；
- **广度开放**：同一父功能下可以并列任意多个子功能；
- **连接开放**：除父子边外，可以有跨层引用/依赖；它们是“额外边”，不替代父子决策安排；
- **内容开放**：每个节点写什么由判断者定，不预设字段/分类；
- **锚点固定**：根是问题，叶是行动/验证；拓扑可以相对展开，但不能没有根和叶。

**“相对”指节点角色相对**：同一个中间节点，对上层是子，对下层是父；不是“从任意节点随意出发”。

---

## 八、内容开放：不预设分类

节点写什么，由具体问题和判断者决定；没有“必须写目标/约束/利益/组织”的模板。

下面只是**示例**，不是模板、不是分类、不是必填项：

```md
# 为什么需要
# 边界/不做什么
# 准备怎么拆/怎么做
# 什么算完成
```

内容可以比示例多，也可以比示例少；关键是写清：**这个节点为什么存在、边界在哪、怎么算完成。**

## 九、与“流程”的区别

|      | 流程        | 决策拓扑                    |
| ---- | --------- | ----------------------- |
| 本质   | 步骤序列      | 父子决策网络                  |
| 是否固定 | 固定步骤      | 不固定，按问题生成               |
| 深度   | 线性        | 根→中间→叶，层数开放             |
| 广度   | 单线        | 同一父功能下可并列               |
| 内容   | 模板        | 开放                      |
| 失败模式 | 跳过步骤/走形式  | 根缺失/叶悬空/越级/不验证          |
| 作用   | 告诉你“先做什么” | 告诉你“决策放在哪、相邻层怎么安排、怎么落地” |

**流程只是参考，不是规则。** 简单问题可以根直接到叶；复杂问题可以拆很多层；规划类可以只拆到“要做什么”的叶子。

## 十、现实成事：与具体情境原生适配

框架不预设“成事必须有哪些要素”。目标、约束、利益、组织、时机、反馈、制度……都只在具体情境里才有意义；框架做的是**让这些情境要素在正确的层级被生成、被安排、被验证、被修正**。

### 9.1 适配机制

1. **根由情境定义**：问题/目标/边界不是套模板，是从具体处境里提取；
2. **拆分由情境决定**：每层拆什么、拆多深，取决于当前情境的主要矛盾/约束，不预设层数；
3. **内容由情境生成**：节点写什么，由判断者在情境中决定，不预设字段；
4. **父功能的实现空间随情境变化**：父功能给子功能的目标/边界/验证标准，是从当前情境推出来的，不是通用清单；
5. **子功能的反馈修正父功能**：实践发现偏差 → 修正父功能的实现空间，而不是硬套原计划；
6. **叶子由情境定义“可落地”**：什么算可执行/可验证，取决于具体资源、时间、人物、标准。

### 9.2 适配效果

- **不套模板**：同一框架在不同情境生成不同网络；简单问题根=叶，复杂问题多层；
- **不漏关键**：父功能必须给子功能定义“为什么/边界/什么算完成”，逼出情境中的关键约束；
- **可落地**：叶子按情境定义，不是概念悬空；
- **可迭代**：实践反馈修正决策，网络越用越贴合现实；
- **可迁移**：换领域只换内容，不换结构。

### 9.3 一句话

> 框架不告诉你“成事有哪些要素”，只保证：**具体情境里的要素，能在正确的层级被生成、被安排、被验证、被修正。**

## 十一、使用方式（最小操作）

1. **定根**：写清问题、目标、边界、总体验证标准；
2. **逐层拆**：每个中间节点只拆自己这一层，用父功能给子功能定义实现空间；
3. **拆到叶**：叶子必须可执行、可验证，不再拆；
4. **决策与行动同步**：行动/代码改动 → 同步节点决策；决策改动 → 行动跟着改；实践发现偏差 → 修正决策，不是改执行再补文档；
5. **行为级验证**：看实际行为+对照决策，不是“文件存在/打勾”；
6. **删除即剪枝**：过时节点直接删，记录原因；
7. **可追溯**：git/记录每次循环，可回滚、可复盘；
8. **判断者拍板高层**：AI/执行者不替代方向/边界/取舍。

## 十三、使用形态：按需外化（不是代价）

框架本身没有使用代价：简单问题可以在脑内走一遍（根=叶，不落文件），成本≈0。只有当你选择“把决策外化”时，才产生记录/维护/验证/协作的成本——这是任何外化系统都有的，不是拓扑特有。

| 形态 | 做法 | 成本 |
|---|---|---|
| **脑内** | 根=叶，不落文件，只在思考里走一遍 | ≈0 |
| **轻量** | 根 + 少量节点，落文件，便于回顾 | 低 |
| **完整** | 多层网络 + git + 行为级验证，用于复杂/协作/长期项目 | 由项目复杂度决定 |

**选择原则**：按“是否需要回顾/协作/追溯/防漂移”决定外化程度；不需要就不外化。

**唯一真正的条件**：外化后需要判断者（定边界/取舍）和维护纪律（同步/删除/验证）——这是“外化”的条件，不是框架的代价。

**一句话**：框架零成本；成本来自你选择外化多少。

## 十四、威力与前提

### 13.1 威力

1. **可生成**：无领域、按复杂度自适应；任何问题都能生成根—中间—叶；
2. **分层决策**：父给边界/目标/验证，子给拆解/执行/反馈；方向与执行不脱节；
3. **可落地**：叶子必须可执行、可验证，不是概念图；
4. **可修正**：决策↔实践循环，越用越准；
5. **可复用**：经验变成拓扑/节点模式，同类问题不用从零想。

### 13.2 前提

| 条件 | 作用 | 框架能否替代 |
|---|---|---|
| **判断者水平** | 定根、边界、取舍、拆到哪停、验证什么 | ❌ 不能替代，是上限 |
| **执行者反馈** | 拆解、执行、反馈真实偏差 | ❌ 不能替代 |
| **纪律** | 同步、删除、验证、不堆垃圾 | ❌ 不能替代，可靠制度约束 |
| **情境信息** | 现实约束、利益、时机、反馈是否真实 | ❌ 不能替代，靠调查 |
| **时间/资源** | 复杂问题需要时间展开 | ❌ 不能替代 |

**唯一不可替代的是判断者的判断力**；其他条件（反馈、纪律、信息、时间）是“成事”的通用条件，不是框架特有的。

### 13.3 一句话

> 框架放大判断，不生产判断；使用者水平决定上限，纪律、信息、反馈决定能不能落地。

## 十六、一句话总结

> **决策网络是一个元框架：以问题为根，节点是功能节点——父功能定义实现空间，子功能在约束下实现并反馈；同一节点可同时承担两种功能；约束是探索实现方案的手段，不是目的；拆到可落地、可验证的叶为止；决策与实践循环互优化，偏差回改实现空间。流程是参考，内容是开放，拓扑是功能关系；父/子功能相对，内容无定式，具体放到具体决策网络里分析。**
