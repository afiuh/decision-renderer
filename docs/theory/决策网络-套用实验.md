# 套用实验：把社区流程装进决策网络

> **目的**：验证决策网络能否“涵盖”社区流程（Spec Kit / BMAD）
> **结论先行**：能套，但套完是“决策化的流程”——每个阶段/角色可以继续无限拆，比原流程更灵活

---

## 1. 实验一：Spec Kit 的 5 阶段

### 1.1 原流程

```
Specify → Plan → Tasks → Implement → Converge
```

每个阶段产出一个 Markdown artifact，喂给下一个阶段。

### 1.2 套进决策网络

```
spec-kit/
├── README.md              ← 这个流程拆成 5 个阶段（每个阶段为什么存在）
├── Specify/README.md      ← 需求规格的决策（为什么做、验收标准）
├── Plan/README.md         ← 技术方案的决策（架构、依赖、风险）
├── Tasks/README.md        ← 任务拆解的决策（顺序、依赖、验收）
├── Implement/README.md    ← 实现的决策（代码组织、测试）
└── Converge/README.md     ← 收敛的决策（对齐、漂移检查）
```

**每个阶段的 README 内部**：

```markdown
# Plan

**父级**：[spec-kit](../README.md)

## 这个阶段做什么

技术方案：架构、依赖、风险。

## 决策

1. 架构：...
2. 依赖：...
3. 风险：...

## 验收

- 当…应…
```

### 1.3 套用结果

| 原流程 | 套用后 |
|---|---|
| 5 个固定阶段 | 5 个模块，**每个模块可以继续拆**（Plan 拆成“架构/依赖/风险”） |
| artifact 链 | 决策文件链（上层的“验收”是下层的“输入”） |
| 无淘汰机制 | **删除即剪枝**（过时的 Plan 决策可以删） |

**能套，而且比原流程更灵活**——原流程的阶段不能拆，我们的每个阶段可以无限拆。

## 2. 实验二：BMAD 的 5 角色

### 2.1 原流程

```
PM → Architect → UX → Dev → QA
```

AI 扮演每个角色，规划先行，BMad Loop 执行。

### 2.2 套进决策网络

```
bmad/
├── README.md              ← 这个流程拆成 5 个角色（每个角色为什么存在）
├── PM/README.md           ← 产品的决策（需求、范围、优先级）
├── Architect/README.md    ← 架构的决策（技术方案、边界）
├── UX/README.md           ← 体验的决策（交互、流程）
├── Dev/README.md          ← 开发的决策（实现、测试）
└── QA/README.md           ← 质量的决策（验收、回归）
```

### 2.3 套用结果

| 原流程 | 套用后 |
|---|---|
| AI 扮演 5 个角色 | **5 个决策视角**（不是 AI 扮演，是人拍板 + AI 整理） |
| 固定角色顺序 | 角色可以按需组合（小项目只需要 PM + Dev） |
| 升级只能问一个开发者 | 每个角色的决策由对应的人拍板（或同一人但明确视角） |

**能套，但“角色”的性质变了**——从“AI 扮演”变成“决策视角”。

---

## 3. 套用后的关键差异

| 维度 | 原流程 | 套进决策网络后 |
|---|---|---|
| **结构** | 固定阶段/角色 | 无限嵌套（每个阶段/角色可以继续拆） |
| **记录** | artifact / 故事 | 决策（为什么 + 验收） |
| **淘汰** | 无 | 删除即剪枝 + commit 原因 |
| **执行者** | AI 扮演 | 人拍板 + AI 执行 |
| **追溯** | spec 历史 / run 历史 | git log decisions |

---

## 4. 为什么能套

因为决策网络的本质是**开放容器**：

- **层级无限**：任何流程的“阶段/角色”都可以变成一个模块
- **内容自定义**：模块内部写什么决策，由流程决定
- **机制不变**：无限嵌套、删除即剪枝、代码同步决策——这些是容器的规则，不是内容

**别人的流程是“内容”（spec 阶段、BMAD 角色），我们的框架是“容器”（模块树 + 决策）。**

---

## 5. 套用的价值

1. **证明涵盖性**：社区流程能装进决策网络，说明我们的框架足够通用
2. **可复用模板**：可以把 Spec Kit / BMAD 做成“preset”（模板），用户按需选择
3. **不牺牲核心**：套用后，决策网络的核心机制（无限嵌套、淘汰、同步）不变

---

## 6. 一句话

**别人的流程是“固定剧本”，我们的框架是“可无限嵌套的舞台”——任何剧本都能上台，但舞台的规则（模块树、决策、淘汰）不变。**
